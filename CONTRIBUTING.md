# Работа с репозиторием

Это внутренний репозиторий команды Flower Cup. Внешние pull request мы не принимаем: см. [LICENSE](LICENSE).

## Ветки и изменения

- `main` всегда в рабочем состоянии: каждый push в неё сразу публикуется на сайт.
- Новые задачи делаются в отдельной ветке и попадают в `main` через pull request. Workflow соберёт сайт на PR и покажет, если что-то сломалось.
- Сообщения коммитов - на английском, в повелительном наклонении: `Add seed care steps`, `Fix order bar on mobile`.

Перед pull request проверьте:

```bash
npm run build     # сборка проходит без ошибок
npm run preview   # сайт открывается, 3D-сцена работает, в консоли нет ошибок
```

Посмотрите изменения на телефоне (около 375 px) и на ноутбуке: на узком экране не должно быть горизонтальной прокрутки, а кнопки и ссылки не должны переноситься на две строки.

## Тексты

- Пишем просто и конкретно, как говорим с покупателем. Без выдуманных цифр и обещаний: если данных нет, их нет и на сайте.
- Вместо длинного тире «—» используем обычный дефис «-».
- Эко-утверждения только проверенные: не пишем про сертификаты, сроки разложения и проценты, пока они не подтверждены документами.

## Дизайн и код

- Цвета и шрифты берутся только из токенов `src/styles/tokens.css` (`var(--color-...)`, `var(--font-...)`). Нужен новый цвет - сначала добавьте токен.
- Анимируем только `transform` и `opacity`. Учитываем `prefers-reduced-motion`.
- Не вставляем HTML из данных через `v-html` и не отключаем CSP в `vite.config.js`.
- Новая зависимость, которая попадает в сайт, записывается в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md). Пакеты под GPL и AGPL не подключаем без согласования.
- Секреты, токены и личные данные в репозиторий не коммитим.

## Контент каталога

Букеты и семена описаны в `src/data/catalog.js`. Новый товар - новая запись в массиве: страница товара и карточка на главной появятся сами. Для иллюстрации букета используйте существующие типы цветов из `src/components/art/Flower.vue`.
