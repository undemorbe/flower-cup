# Безопасность

## Как сообщить об уязвимости

Если вы нашли уязвимость на сайте Flower Cup или в этом репозитории, напишите нам в Telegram: [@polyvinylchlorid](https://t.me/polyvinylchlorid). Пожалуйста, не создавайте публичный issue и не публикуйте детали, пока мы не выпустим исправление.

В сообщении укажите:

- что именно не так и на какой странице или в каком файле;
- шаги, чтобы воспроизвести проблему;
- чем она может грозить посетителям сайта или нам.

Мы ответим, как только прочитаем сообщение, и расскажем, когда ждать исправления. Денежного вознаграждения за найденные уязвимости у нас пока нет, но мы с радостью поблагодарим вас публично, если вы не против.

## Что входит в проверку

- сайт, собранный из ветки `main` и опубликованный на GitHub Pages;
- бэкенд из `server/` и конфигурация из `deploy/`;
- код в этом репозитории, включая workflow GitHub Actions.

Не входят: Telegram и GitHub как платформы, хостинг-провайдер сервера, а также атаки, которые требуют физического доступа к устройству посетителя.

## Как устроена защита

### Сайт

- Посетители не вводят персональных данных: нет форм, оплаты, cookie и аналитики. Заказ уходит в Telegram.
- В браузере хранятся только выбранные букет и семечко, дата посадки и демо-черновик админки. Всё это при чтении проверяется: слаги по шаблону, даты в разумных пределах, черновик - полной схемой.
- Контент из API проходит ту же схему, что и на сервере. Цель QR-кода собирается только во внутренний путь сайта - внешних редиректов нет.
- Пользовательский текст не вставляется как HTML, Vue экранирует весь вывод. В JSON-LD экранируется `<`.
- CSP: скрипты, стили, шрифты и изображения только с нашего домена, запросы - только к своему API.
- Админка открывается по адресу из `VITE_ADMIN_PATH`, закрыта `noindex` и не упоминается в `robots.txt`. Без бэкенда она работает в демо-режиме: правки не покидают браузер.

### Бэкенд

- Пароль админки хранится только как scrypt-хеш (`ADMIN_PASSWORD_HASH`), сравнение - за постоянное время.
- Сессия - токен с HMAC-подписью и сроком жизни (по умолчанию 12 часов), хранится в `sessionStorage`, отправляется заголовком `Authorization`, cookie не используются - CSRF неприменим.
- Вход: не больше 5 попыток за 15 минут с адреса (и ещё 5 в минуту на nginx). За nginx адрес клиента берётся из `X-Forwarded-For`, который nginx перезаписывает - подделать его нельзя.
- Админские запросы принимаются только с сайтов из `ALLOWED_ORIGINS`. Публичные `GET` открыты всем, но отдают только опубликованное, без служебных пометок.
- Тело запроса - только JSON до 256 КБ. Каждое изменение проходит схему: неизвестные поля отбрасываются, строки чистятся от управляющих символов, проверяются связи между записями.
- Ревизии защищают от затирания чужих правок, перед каждым изменением делается резервная копия. Файлы данных создаются с правами `0600`.
- Ошибки сервера не раскрывают внутренности. Секреты - только в переменных окружения, `server/.env` в `.gitignore`.
- systemd-юнит запускает бэкенд под отдельным пользователем в песочнице (`ProtectSystem=strict`, запись только в каталог данных). Сервер слушает `127.0.0.1`, наружу его выставляет nginx с TLS и защитными заголовками.

### Сборка

- В GitHub Actions токен по умолчанию только читает, права на публикацию есть лишь у шага деплоя. Сторонние actions закреплены по SHA коммита.
- Сборка останавливается, если не проходят тесты или `npm audit` находит серьёзную уязвимость. Dependabot раз в неделю предлагает обновления. У бэкенда нет зависимостей.

## Известные ограничения

- GitHub Pages не позволяет задавать HTTP-заголовки, поэтому `frame-ancestors` / `X-Frame-Options` для сайта там не работают. В варианте с nginx (`deploy/nginx/flower-cup-site.conf`) они есть.
- Адрес админки виден в JavaScript-бандле внимательному человеку. Это маскировка от ботов, а не защита - защиту даёт пароль.
- `robots.txt` проектного сайта (`/<repo>/robots.txt`) поисковики не читают: настоящая защита от индексации - meta `noindex` на админке и QR-страницах.
- Счётчик сканирований QR приблизительный: лимит 60 засчитанных переходов в минуту с адреса.
