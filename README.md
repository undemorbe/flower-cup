# Flower Cup

**Букет, который продолжает жить.**

Flower Cup - эко-стартап, который продаёт букеты в биоразлагаемых крафтовых стаканчиках вместо пластиковой упаковки и вазы. На дне каждого стаканчика лежит конвертик с семенами: когда букет отцветёт, в этом же стаканчике можно вырастить новое растение, а потом посадить его в землю вместе со стаканчиком.

Сайт: https://undemorbe.github.io/flower-cup/ · Заказы: [Telegram @polyvinylchlorid](https://t.me/polyvinylchlorid)

## О продукте

Обычный букет - это цветы плюс плёнка, лента, коробка и ваза. Почти всё, кроме цветов, через неделю отправляется в мусор. Мы убираем этот слой:

- **Стаканчик вместо вазы.** Цветы сразу стоят в воде в плотном стаканчике из крафт-картона.
- **Без пластика и лишней упаковки.** Клиент платит за цветы, а не за обёртку, поэтому букет обходится дешевле.
- **Вторая жизнь.** Семечко на дне превращает отцветший букет в начало нового растения.

### Жизнь одного стаканчика

1. **Стоит как в вазе.** Вода наливается прямо в стаканчик.
2. **Букет отцвёл.** Цветы - в компост, стаканчик остаётся.
3. **Семечко на дне.** В стаканчик насыпают землю и сеют семена из конвертика.
4. **Прямо в землю.** Окрепший росток сажают в горшок или грунт вместе со стаканчиком, корни не тревожат.

### Ассортимент

- **Букеты:** «Полевые цветы», «Роза в поле», «Лаванда», «Подсолнух».
- **Семена на выбор:** базилик, подсолнечник, ромашка аптечная, лаванда, василёк синий, настурция.

Клиент сам выбирает, какое семечко положить в стаканчик. Заказ оформляется в Telegram: сайт формирует сообщение с выбранным букетом и семенами.

## Сайт

Мобильное веб-приложение в одной вкладке: разделы и карточки открываются с анимацией внутри того же окна, есть кнопка «назад» и нижняя панель вкладок на телефоне.

- **Главная** `/`: 3D-стаканчик с букетом, тизеры разделов.
- **Букеты** `/bouquets`, **букет** `/bouquets/:slug`: состав, выбор семечка, уход, заказ.
- **Растения** `/plants`, **растение** `/plants/:slug`: условия, инструкция, трекер «Мой стаканчик» (дата посадки хранится в браузере).
- **QR-ссылки** `/q/:code`: короткий адрес для QR на стаканчике, ведёт на страницу растения с приветствием.
- **Вопросы** `/faq`, **отзывы** `/reviews`, **контакты** `/contacts`, разделы из админки `/:slug` (например `/about`, `/cups`).
- **Своя страница 404** - и для неизвестных адресов, и для удалённых букетов, растений, QR-кодов.
- **Заказ:** букет и семечко отправляются в Telegram готовым сообщением.

Иллюстрации нарисованы кодом (SVG), 3D-сцена собрана процедурно на three.js.

### Архитектура

```
shared/          общий код сайта, сборки и бэкенда
  schema.js        схема контента: валидация, очистка ввода, связи, публичный вид
  mutations.js     изменения из админки (добавить, удалить, переставить, переименовать)
  seed-content.json  mock-контент: на нём сайт работает без бэкенда
  admin-path.js    проверка секретного адреса админки
src/
  content/store.js  откуда брать контент: снимок в HTML -> API -> демо-черновик
  router.js         маршруты, анимации переходов, восстановление прокрутки
  seo/head.js       title, description, canonical, Open Graph, JSON-LD
  admin/            админка: формы по схеме, QR-коды, два режима (API и демо)
  views/ components/ composables/
server/           микро-бэкенд на node:http без зависимостей
deploy/           nginx и systemd для своего сервера
scripts/prerender.mjs  статический HTML всех страниц, 404.html, sitemap.xml, robots.txt
tests/            vitest
```

**Контент без бэкенда.** Сайт всегда собирается с готовым контентом: при сборке он берётся из API (`CONTENT_API_URL`), а если API не задан или не ответил - из `shared/seed-content.json`. Снимок встраивается в каждую страницу. Если при сборке задан `VITE_API_URL`, браузер дополнительно подтягивает свежие данные из API; не ответил за 6 секунд - сайт остаётся на снимке.

**SEO.** Каждая страница пререндерится в статический HTML с заголовком, описанием, canonical, Open Graph и разметкой schema.org (Organization, Product, HowTo, FAQPage, BreadcrumbList). Генерируются `sitemap.xml` и `robots.txt`. Админка и QR-переходы закрыты `noindex`. Картинка для соцсетей подключится сама, если положить `public/og.png` (1200x630).

### Админка

Адрес задаётся при сборке переменной `VITE_ADMIN_PATH` (по умолчанию `/studio-fc`, `/admin` - обычная 404). Адрес не публикуется в `robots.txt` и sitemap. Это не защита, а маскировка: настоящую защиту даёт пароль на бэкенде.

- **Без бэкенда - демо-режим (mock).** Правки сохраняются только в этом браузере и сразу видны на сайте в нём же. Удобно показать, как всё работает. Кнопка «Сбросить демо» возвращает исходный контент.
- **С бэкендом** - вход по паролю, правки сохраняются на сервере, сайт пересобирается автоматически (если настроен `GITHUB_TOKEN`).

Что можно менять: разделы (блоки: фраза, текст, тезисы, этапы, кнопка), букеты, растения, вопросы, отзывы, QR-коды, контакты и SEO-тексты. Для каждого QR-кода есть предпросмотр, скачивание SVG/PNG для печати и счётчик сканирований.

### Стек

- [Vue 3](https://vuejs.org) + [Vue Router](https://router.vuejs.org), сборка [Vite](https://vite.dev), тесты [Vitest](https://vitest.dev)
- [three.js](https://threejs.org) для 3D-сцены, [qrcode-generator](https://github.com/kazuhikoarase/qrcode-generator) для QR в админке - обе загружаются отдельными чанками
- Бэкенд: Node.js 22+, только стандартная библиотека
- Шрифты Cormorant Garamond, Rubik и Marck Script через [Fontsource](https://fontsource.org), раздаются с нашего домена

## Разработка

Нужен Node.js 22 или новее.

```bash
npm install
npm run dev       # сайт на http://localhost:5173, админка - /studio-fc (демо-режим)
npm test          # тесты
npm run build     # сборка + пререндер в dist/
npm run preview   # посмотреть собранный сайт
```

### Бэкенд локально

```bash
cp server/.env.example server/.env
npm run admin:hash          # спросит пароль, выведет ADMIN_PASSWORD_HASH
openssl rand -base64 48     # SESSION_SECRET
npm run server:dev          # API на http://127.0.0.1:8787
VITE_API_URL=http://127.0.0.1:8787 npm run dev
```

Данные хранятся в `server/data/content.json` (+ 30 резервных копий в `server/data/backups/`). Каталог в `.gitignore`.

API: `GET /api/content`, `GET /api/qr/:code`, `POST /api/admin/login`, `GET /api/admin/content`, `POST /api/admin/changes`.

## Деплой

### Сайт на GitHub Pages

Workflow `.github/workflows/deploy.yml` на каждый push в `main` прогоняет тесты, собирает и публикует сайт. Pull request только проверяется. Один раз: **Settings → Pages → Source: GitHub Actions**.

GitHub Pages сам отдаёт `404.html` на любой незнакомый адрес - это наша страница 404, внутри которой стартует приложение (так открываются разделы и QR-коды, созданные после сборки).

Необязательные настройки в **Settings → Secrets and variables → Actions**:

| Где | Имя | Что |
| --- | --- | --- |
| Variables | `API_URL` | адрес бэкенда, например `https://api.example.ru`. Без него - mock-данные |
| Variables | `SITE_URL` | свой домен (canonical, sitemap) |
| Secrets | `ADMIN_PATH` | адрес админки, например `/kabinet-7f3k` |

### Бэкенд на своём сервере (nginx)

GitHub Pages не запускает серверный код, поэтому бэкенд живёт на VPS за nginx, а сайт на Pages обращается к нему по `API_URL`.

1. Код и systemd-юнит - инструкция в шапке `deploy/flower-cup-api.service`.
2. `/etc/flower-cup.env`: пароль, секрет, `TRUST_PROXY=1`, `ALLOWED_ORIGINS=https://undemorbe.github.io`.
3. nginx: `deploy/nginx/flower-cup-api.conf` + сниппеты из `deploy/nginx/snippets/`, сертификат через certbot.
4. В GitHub задать `API_URL`. Чтобы сайт пересобирался после правок в админке - `GITHUB_TOKEN` в env бэкенда (fine-grained, только этот репозиторий, Actions: write).

Нужен весь сайт на своём домене без GitHub Pages - `deploy/nginx/flower-cup-site.conf`: статика из `dist/` (сборка с `BASE_PATH=/`), своя 404 с настоящим статусом 404, кеширование, защитные заголовки и API на том же домене.

## Безопасность

Бэкенд: пароль хранится только как scrypt-хеш, сессии - подписанные токены с ограниченным сроком, лимит попыток входа, CORS по списку, все входные данные проходят схему. Сайт: CSP, вывод только через экранирование Vue, данные из браузера и API проверяются. Подробно и как сообщить об уязвимости - в [SECURITY.md](SECURITY.md).
